> **R1 → R2 修订说明（2026-10-23）**
> R1 把本项目定义为「传文件 + 转发端口的工具」，场景都是**两台机器**之间。
> 实际需求是 **组网**：N 台机器、同一身份多设备、任意两台可直达、每台都是节点。
> 这不是范围扩大，是产品定义变了。R1 的传输与转发能力在组网里仍然有用（见 §3.5），
> 但它们是**能力**，不是**产品**。

## 1. 问题定义

### 1.1 一句话

把散落在各处的机器（云服务器、受限容器、家里的机器、笔记本）连成一张**自己的网**：
同一个身份下的设备互相可见、可直接通信、可互传大文件，不依赖任何中心服务，
不需要公网 IP，不需要 root。

### 1.2 与 R1 的关键差异

| 维度 | R1（旧） | R2（本版） |
|---|---|---|
| 拓扑 | 两台，一对一配对 | **N 台，任意两台** |
| 身份 | 一个临时 code，用完即弃 | **长期身份（密钥对），多设备共存** |
| 中继 | 必需的专用服务器 | **节点自己就能当中转**（可选加速） |
| 数据路径 | 全部经中继 | **优先直连，失败才经其他节点中转** |
| 用户心智 | 「传个文件」 | 「我的设备组成一张网」 |

### 1.3 这不是什么

| 不是 | 为什么 |
|---|---|
| 不是 VPN | 无 `CAP_NET_ADMIN` 时做不了透明 L3（含 subnet router、exit node 类全流量接管）；能做的那部分（单服务暴露）见 R-4.5 / R-5.4 |
| 不是 Tailscale 的复刻 | 不实现 WireGuard、不做内核态；我们是用户态、零特权的替代路线 |
| 不是文件同步 | 不做持续双向同步、不做冲突合并 |
| 不是多租户 SaaS | 一个身份就是一个人/一个团队，不做账号体系与计费 |

## 2. 用户与场景

### 2.1 用户

| 编号 | 用户 | 处境 |
|---|---|---|
| **U1** | 个人开发者 | 有 2–10 台机器：笔记本、几台云服务器、几个受限容器。要它们互相通 |
| **U2** | 小团队 | 每人多台设备，团队内要共享某些服务（数据库、内部 API）。**R3 定案：共享团队身份**——一个身份=一个团队，成员设备进同一成员列表、全员互信；共享服务天然满足。隔离型 ACL/多身份不做（N-8），留给阶段 4 |
| **U3** | 受限环境使用者 | K8s Pod / 云函数 / 托管容器：无 root、无入站端口、无 TUN |

**U1 是首要目标。** 先让一个人自己的 5 台机器连成网，比先支持 500 台更有价值。

### 2.2 核心场景

**S1 — 我的设备互相看见**
笔记本、云服务器 A、云服务器 B、家里的 NAS 都登同一个身份。任意一台上执行
`cmesh status`，能看到其余三台在线、各自的地址与延迟。

**S2 — 从笔记本直接操作云服务器上的服务**
云服务器上的数据库只听 `127.0.0.1:5432`。笔记本上 `cmesh forward` 或直接
`cmesh dial db` 就能连，**不需要知道那台机器的公网 IP**。

**S3 — 两台设备互传大文件**
笔记本 → NAS，10 GB。要快（不慢于 scp 的合理比例），中断可续传。

**S4 — 两台都在 NAT 后**
笔记本在家里、服务器在办公室内网，两边都没公网 IP。要么打洞直连，
要么经第三台（有公网的那台云服务器）中转。

**S5 — 受限容器加入网**
K8s Pod 里跑一个 agent，无 root、无入站端口，但能出站。它要能被网内其他设备访问。

### 2.3 明确不考虑

- 需要 `ping` 通对方（见 §4.1 硬边界）
- 数百台以上的规模（先做到几十台稳定）
- 跨组织的信任联邦（一个身份就是信任边界）

## 3. 功能需求

优先级：**P0** = 没有它组网不成立；**P1** = 核心场景需要；**P2** = 有用可延后。

### 3.1 身份（阶段 2，核心）

| 编号 | 需求 | 优先级 | 状态 |
|---|---|---|---|
| **R-1.1** | 每台设备持有长期密钥对，公钥即身份 | P0 | ✅（PR-M1） |
| **R-1.2** | 同一身份下多设备共存，设备间互相认证 | P0 | 部分（证书/成员列表已实现；组网握手未接） |
| **R-1.3** | 设备可单独撤销；撤销后其**已建立的会话**在一个推送往返内被销毁（不只是拒绝新连接） | P0 | 部分（成员除名已实现；会话销毁待通信层） |
| **R-1.4** | 身份密钥加密存储在本地，不依赖任何服务器（受限环境须支持挂载注入，如 K8s Secret） | P0 | 部分（本地加密存储 ✅ PR-M1；挂载注入路径未验证） |
| **R-1.5** | 加入网络必须持有效邀请与身份证书；无凭证的加入尝试一律被拒（可判定：没有「猜口令」这个攻击面） | P0 | ✅（invite/join/authorize/证书收编全流程落地，PR-M2 二刀） |
| **R-1.6** | 设备名、标签等元数据可读可改 | P1 | 部分（设备名可读可设；改名 CLI 未实现） |

### 3.2 发现与拓扑（阶段 2，核心）

| 编号 | 需求 | 优先级 | 状态 |
|---|---|---|---|
| **R-2.1** | 节点自动发现彼此，无需手工配置 IP 列表 | P0 | 部分（状态机+HTTP/WS 传输+心跳+CLI 全链路已通，三节点集成验收过；真实 WAN 部署验收待 PR-M5 前） |
| **R-2.2** | 拓扑变化（上线/下线/换 IP）秒级收敛：异常掉线 ≤10 s（传输层断连检测），优雅下线 ≤3 s | P0 | 部分（**快路径已实现**：members 流断开→立即下线推送，实测 0.01s；10s idle 兜底硬杀；优雅下线 LEAVE 广播未实现） |
| **R-2.3** | 任一节点可查询全网成员与连通状态（CLI 查询形态；图形视图仍归 R-6.x） | P0 | 部分（join/serve-discovery 已实时打印成员视图；独立 `cmesh status` 命令待做） |
| **R-2.4** | 发现层不暴露给非成员：外部无法枚举网内设备 | P0 | ✅（注册/订阅双门签名认证 + 限流；客户端侧逐证书验证——恶意发现节点无法伪造成员） |
| **R-2.5** | 无中心也能工作：至少一个节点可达即可（可以是任意成员） | P1 | ❌ |

### 3.3 连接与路由（阶段 2，核心）

| 编号 | 需求 | 优先级 | 状态 |
|---|---|---|---|
| **R-3.1** | 优先直连：能打洞就走 P2P，不经任何中转 | P0 | 部分（组网直连层可用：成员视图端点解析 + mTLS 设备证书认证 + `mesh ping`/`dial`；NAT 自动打洞编排未接） |
| **R-3.2** | 直连失败时，经网内其他节点中转（**不是**专用中继） | P0 | ❌ |
| **R-3.3** | 中转路径自动选择，用户不需要指定走哪台 | P1 | ❌ |
| **R-3.4** | 路径可切换：直连断了自动退回中转，恢复后自动切回 | P1 | ❌ |
| **R-3.5** | 中转节点**不知通信内容**（端到端加密）。它为建路必然知道路径端点，但无法解密——验收口径是「抓包无明文」，不是「不知任何元数据」 | P0 | ❌ |
| **R-3.6** | 转发有配额：单节点被当跳板时有上限，不拖垮自己 | P1 | ❌ |

### 3.4 通信能力（阶段 2）

| 编号 | 需求 | 优先级 | 状态 |
|---|---|---|---|
| **R-4.1** | 任意两台之间可发消息，低延迟（直连同机房按 P-1：<5 ms p95） | P0 | ✅（按名消息 `cmesh msg` 实时投递 + `mesh ping` p95 0.27ms 实测；SIGMA e2e 层在 PR-M4 叠加） |
| **R-4.2** | 任意两台之间可传文件，支持大文件与断点续传 | P0 | 部分（按名传输 `cmesh send-to`：100MB @ 72.3 MB/s 实测、sha256 校验 ✓；组网内断点续传待 PR-M5） |
| **R-4.3** | 一条连接承载多路复用（消息 + 文件 + 转发共存） | P0 | ✅ 已有 |
| **R-4.4** | 按设备名寻址，不用记 IP | P1 | ✅（msg/send-to/run/ping/dial 全部按 16 位设备名寻址，端点自动解析；人类可读别名未做） |
| **R-4.5** | 任意两台之间可开端口转发（把某台的服务暴露给网内） | P1 | ✅ 能力已有 |

## 4. 非功能需求

### 4.1 硬边界（做不到的，明确写出来）

| 编号 | 做不到 | 原因 |
|---|---|---|
| **N-1** | 无 TUN 时 `ping` 通对端 | 内核没有接口承载该路由，无 workaround |
| **N-2** | 无 TUN 时 `ssh user@100.64.0.5` 直连 | 同上，必须走 `cmesh` 子命令或代理参数 |
| **N-3** | 让不感知代理的进程透明走网 | 无 TUN/路由钩子就没有重定向点；`LD_PRELOAD` 类手段只覆盖本进程及子进程，不是通用解 |
| **N-4** | 对称 NAT × 对称 NAT 之间直连 | 无解，必须经第三方中转（R-3.2 覆盖） |
| **N-5** | SCTP / 任意 IP 协议；UDP 服务的转发语义受限（`-L` 仅 TCP） | 用户态 netstack 不实现 |
| **N-6** | 数百台规模的全局路由收敛 | 先做几十台；规模上去需要 DHT 或分层，是另一个阶段 |
| **N-7** | 不修改系统 DNS 配置时的网内域名解析（MagicDNS 类） | 无 TUN 时对系统不透明；设备名寻址走 `cmesh` 子命令（R-4.4） |
| **N-8** | 跨身份互通与跨身份 ACL | 一个身份就是一个信任边界（§1.3），不做身份间联邦 |
| **N-9** | 「全网均不可达」时保证通信 | 对称 NAT × 对称 NAT 且网内无可达中转节点时无解；通信前提是 C-3 的「至少一个节点可达」 |
| **N-10** | 无 root/`CAP_NET_BIND_SERVICE` 时本地监听 <1024 端口 | 内核限制；转发到本机低位端口（22/53/80）需特权或调整 `ip_unprivileged_port_start` |

### 4.2 性能门槛

| 编号 | 指标 | 门槛 | 说明 |
|---|---|---|---|
| **P-1** | 同机房两台直连的往返延迟 | **< 5 ms**（p95） | 打洞直连，不经中转 |
| **P-2** | 同机房经中转的往返延迟 | < 20 ms（p95） | 多一跳 |
| **P-3** | 直连大文件吞吐 | **≥ 200 MiB/s** | 相对阶段 1 的 515 MiB/s 打余量 |
| **P-4** | 经中转的大文件吞吐 | ≥ 50 MiB/s | 中转节点是瓶颈 |
| **P-5** | 拓扑收敛：**异常掉线**（kill -9 / 断网） | < 10 s | 由传输层断连检测保证，不是心跳轮询 |
| **P-5b** | 拓扑收敛：**优雅下线**（主动退出） | < 3 s | 显式 LEAVE 广播 |
| **P-6** | 单节点 20 台设备时的 RSS | < 100 MiB | |
| **P-7** | 中转配额 | 单节点默认 ≤ 50 MiB/s、≤ 20 条流 | 防止被当免费跳板 |

### 4.3 兼容性

| 编号 | 要求 |
|---|---|
| **C-1** | 无界面的 CLI / 锚点保持单二进制静态链接，无 CGO、无运行时依赖；R-6.5 图形客户端单独打包，可使用系统 WebView 与原生桥，不把桌面运行库带入容器版本 |
| **C-2** | CLI / 锚点支持 linux/amd64、linux/arm64、darwin/amd64、darwin/arm64、windows/amd64；图形客户端的平台范围和验收另见 R-6.5 |
| **C-3** | 客户端零入站端口；至少一个节点可达即可（不要求固定某台） |
| **C-4** | 协议向后兼容：新增帧类型不升版本号，靠 `caps` 协商 |
| **C-5** | 传输必须能穿过仅允许 HTTP(S)/WebSocket 出站的环境（代理、CDN 前置）——U3 受限容器场景的准入条件 |

### 4.4 运维要求

| 编号 | 要求 |
|---|---|
| **O-1** | 节点无状态：本地只存身份密钥与配置，不存路由表持久化 |
| **O-2** | 任一节点可重启，不影响其他节点之间的连通 |
| **O-3** | 加入网络只需一个邀请（不是一串 IP 列表） |
| **O-4** | 一条命令启动，失败时给出可操作的错误信息 |
| **O-5** | 邀请是一个可传递的单串（载体明确），有默认有效期、一次性、可撤销语义；过期/已用/已撤销的邀请报可操作错误 |
| **O-6** | 自举零配置：邀请自带发现节点种子端点；首台设备默认成为发现节点；种子全部不可达时报可操作错误 |
| **O-7** | 本地监听端口被占用时报可操作错误，并给出替代端口建议 |
| **O-8** | `cmesh doctor`：报告 TUN/出站/端口等环境能力（复用 internal/probe），用于失败诊断（P2） |

## 5. 验收标准

### 5.1 阶段 2 验收（组网，未开始）

| 项 | 标准 |
|---|---|
| 三节点直连 | 三台同机房机器，任意两台 `cmesh ping`（自定义 RTT）< 5 ms（p95，P-1） |
| 多设备身份 | 同一身份下 4 台设备互相可见，`cmesh status` 全部列出（依赖 R-2.3，P0） |
| 中转 | 人为阻断 A↔C 直连，A→C 自动经 B 中转，仍可通（P0 只要求确定性选中首个可用中转；择优选路归 R-3.3） |
| 中转延迟 | 强制走中转的 RTT < 20 ms（p95，P-2） |
| 大文件 | 直连 ≥ 200 MiB/s，经中转 ≥ 50 MiB/s，SHA-256 一致 |
| 异常掉线收敛 | `kill -9` 一台节点，其余 ≤10 s 感知并更新拓扑（P-5；与优雅下线 P-5b 分测） |
| 非成员隔离 | 无成员凭证的注册/查询/订阅请求逐端点全部被拒（R-2.4） |
| 撤销 | 撤销一台设备的身份，其活跃会话在一个推送往返内被销毁且无法重连，其他设备不受影响（可判定形式：撤销广播后 ≤ 30 s 内旧会话拆毁、新握手被拒；机制是发现节点推送，30 s 是测试断言的宽限上限，不是等心跳或重连才发现） |
| 端到端加密 | 中转节点抓包看不到明文 |
| 配额 | 单节点被持续转发时，吞吐 ≤ 50 MiB/s、流数 ≤ 20（P-7），且自身业务不受影响 |
| 资源 | 单节点承载 20 台设备在线，RSS < 100 MiB（P-6） |

### 5.2 每轮迭代的验收门槛

见 [`CONVENTIONS.md`](CONVENTIONS.md) §6 检查清单。核心五条：

1. `gofmt` / `vet` / `build` 全干净
