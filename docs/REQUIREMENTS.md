## 1. 问题定义

### 1.1 一句话

把散落在各处的机器（云服务器、受限容器、家里的机器、笔记本）连成一张**自己的网**：
同一个身份下的设备互相可见、可直接通信、可互传大文件，不依赖任何中心服务，
不需要公网 IP，不需要 root。

### 1.2 基线演进

产品定义的每次变更（R1→R2→R3）、变更原因与关键差异，见 [`decisions.md`](decisions.md)。
本文只描述当前基线，不保留历史对照。

### 1.3 这不是什么

| 不是 | 为什么 |
|---|---|
| 不是 VPN | 无 `CAP_NET_ADMIN` 时做不了透明 L3（含 subnet router、exit node 类全流量接管）；能做的那部分（单服务暴露）见 R-4.5 / R-5.4 |
| 不是 Tailscale 的复刻 | 不实现 WireGuard、不做内核态；我们是用户态、零特权的替代路线 |
| 不是文件同步 | 不做持续双向同步、不做冲突合并 |
| 不是多租户 SaaS | 一个身份就是一个人/一个团队，不做账号体系与计费 |

## 2. 用户与场景

### 2.1 用户

| 编号 | 用户 | 处境 |
|---|---|---|
| **U1** | 个人开发者 | 有 2–10 台机器：笔记本、几台云服务器、几个受限容器。要它们互相通 |
| **U2** | 小团队 | 每人多台设备，团队内要共享某些服务（数据库、内部 API）。**R3 定案：共享团队身份**——一个身份=一个团队，成员设备进同一成员列表、全员互信；共享服务天然满足。隔离型 ACL/多身份不做（N-8），留给阶段 4 |
| **U3** | 受限环境使用者 | K8s Pod / 云函数 / 托管容器：无 root、无入站端口、无 TUN |

**U1 是首要目标。** 先让一个人自己的 5 台机器连成网，比先支持 500 台更有价值。

### 2.2 核心场景

**S1 — 我的设备互相看见**
笔记本、云服务器 A、云服务器 B、家里的 NAS 都登同一个身份。任意一台上执行
`cmesh status`，能看到其余三台在线、各自的地址与延迟。

**S2 — 从笔记本直接操作云服务器上的服务**
云服务器上的数据库只听 `127.0.0.1:5432`。笔记本上 `cmesh forward` 或直接
`cmesh dial db` 就能连，**不需要知道那台机器的公网 IP**。

**S3 — 两台设备互传大文件**
笔记本 → NAS，10 GB。要快（不慢于 scp 的合理比例），中断可续传。

**S4 — 两台都在 NAT 后**
笔记本在家里、服务器在办公室内网，两边都没公网 IP。要么打洞直连，
要么经第三台（有公网的那台云服务器）中转。

**S5 — 受限容器加入网**
K8s Pod 里跑一个 agent，无 root、无入站端口，但能出站。它要能被网内其他设备访问。

### 2.3 明确不考虑

- 需要 `ping` 通对方（见 §4.1 硬边界）
- 数百台以上的规模（先做到几十台稳定）
- 跨组织的信任联邦（一个身份就是信任边界）

## 3. 功能需求

优先级：**P0** = 没有它组网不成立；**P1** = 核心场景需要；**P2** = 有用可延后。

### 3.1 身份（阶段 2，核心）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| **R-1.1** | 每台设备持有长期密钥对，公钥即身份 | P0 |
| **R-1.2** | 同一身份下多设备共存，设备间互相认证 | P0 |
| **R-1.3** | 设备可单独撤销；撤销后其**已建立的会话**在一个推送往返内被销毁（不只是拒绝新连接） | P0 |
| **R-1.4** | 身份密钥加密存储在本地，不依赖任何服务器（受限环境须支持挂载注入，如 K8s Secret） | P0 |
| **R-1.5** | 加入网络必须持有效邀请与身份证书；无凭证的加入尝试一律被拒（可判定：没有「猜口令」这个攻击面） | P0 |
| **R-1.6** | 设备名、标签等元数据可读可改 | P1 |

### 3.2 发现与拓扑（阶段 2，核心）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| **R-2.1** | 节点自动发现彼此，无需手工配置 IP 列表 | P0 |
| **R-2.2** | 拓扑变化（上线/下线/换 IP）秒级收敛：异常掉线 ≤10 s（传输层断连检测），优雅下线 ≤3 s | P0 |
| **R-2.3** | 任一节点可查询全网成员与连通状态（CLI 查询形态；图形视图仍归 R-6.x） | P0 |
| **R-2.4** | 发现层不暴露给非成员：外部无法枚举网内设备 | P0 |
| **R-2.5** | 无中心也能工作：至少一个节点可达即可（可以是任意成员） | P1 |

### 3.3 连接与路由（阶段 2，核心）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| **R-3.1** | 优先直连：能打洞就走 P2P，不经任何中转 | P0 |
| **R-3.2** | 直连失败时，经网内其他节点中转（**不是**专用中继）。**中转是「可用可不用」的自愿能力（网主 2026-11-24 裁定，R4）**：默认关、**永不自动开启**；不开启中转的节点与普通成员**无区别**（不承载、不转发他人流量）。**开启三闸，缺一不可**：① **公开可达性检测通过**——由网内另一节点从外部做**反向拨号**验证（唯一能证明「别人连得进来」的判据；本机公网地址与 STUN 反射均不构成判据）→ ② 运维**显式开启**（**面板开关**；启动参数与信号是同一开关的等价入口）→ ③ 按 P-7 配额承接。**关闭立即生效**：停止承载新中转，并拆掉正在承载的流。中转方限定为**有公网可达的锚点**；纯出站成员主动连锚点、经锚点中转；连接顺序：直连优先（能打洞则打洞），直连不可行才降级中转。是否放开「任意成员当中转方」由后续开关决定 | P0 |
| **R-3.3** | 中转路径自动选择，用户不需要指定走哪台 | P1 |
| **R-3.4** | 路径可切换：直连断了自动退回中转，恢复后自动切回 | P1 |
| **R-3.5** | 中转节点**不知通信内容**（端到端加密）。它为建路必然知道路径端点，但无法解密——验收口径是「抓包无明文」，不是「不知任何元数据」 | P0 |
| **R-3.6** | 转发有配额：单节点被当跳板时有上限，不拖垮自己 | P1 |

### 3.4 通信能力（阶段 2）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| **R-4.1** | 任意两台之间可发消息，低延迟（直连同机房按 P-1：<5 ms p95） | P0 |
| **R-4.2** | 任意两台之间可传文件，支持大文件与断点续传 | P0 |
| **R-4.3** | 一条连接承载多路复用（消息 + 文件 + 转发共存） | P0 |
| **R-4.4** | 按设备名寻址，不用记 IP | P1 |
| **R-4.5** | 任意两台之间可开端口转发（把某台的服务暴露给网内） | P1 |

### 3.5 已有能力（阶段 1，冻结但保留）

阶段 1 交付的这些能力在组网里**继续有效**，只是暂时不继续投入：

| 编号 | 能力 | 在组网里的角色 |
| --- | --- | --- |
| **R-5.1** | SPAKE2 握手 + AES-256-GCM | 可复用为会话加密（长期身份另需密钥交换） |
| **R-5.2** | 记录泵 + yamux 多路复用 | 直接复用：组网也是多流复用 |
| **R-5.3** | 打洞 + QUIC 直连 | **组网的核心**：直连层 |
| **R-5.4** | `-L` / `-R` 端口转发 | 组网里的一个能力（R-4.5） |
| **R-5.5** | 文件传输 + 断点续传 + 校验 | 组网里的一个能力（R-4.2） |
| **R-5.6** | 中继配对 + 限流 + 状态看板 | 可演化为「发现节点」 |

**冻结的含义**：不再新增功能、不再优化，但**不删除**、不破坏。
组网需要它们时直接复用。

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| **R-6.1** | 看到网内所有设备与在线状态 | P2 |
| **R-6.2** | 看到拓扑：谁和谁直连、谁经谁中转 | P2 |
| **R-6.3** | 看到每台设备的实测延迟与带宽 | P2 |

## 4. 非功能需求

### 4.1 硬边界（做不到的，明确写出来）

| 编号 | 做不到 | 原因 |
|---|---|---|
| **N-1** | 无 TUN 时 `ping` 通对端 | 内核没有接口承载该路由，无 workaround |
| **N-2** | 无 TUN 时 `ssh user@100.64.0.5` 直连 | 同上，必须走 `cmesh` 子命令或代理参数 |
| **N-3** | 让不感知代理的进程透明走网 | 无 TUN/路由钩子就没有重定向点；`LD_PRELOAD` 类手段只覆盖本进程及子进程，不是通用解 |
| **N-4** | 对称 NAT × 对称 NAT 之间直连 | 无解，必须经第三方中转（R-3.2 覆盖） |
| **N-5** | SCTP / 任意 IP 协议；UDP 服务的转发语义受限（`-L` 仅 TCP） | 用户态 netstack 不实现 |
| **N-6** | 数百台规模的全局路由收敛 | 先做几十台；规模上去需要 DHT 或分层，是另一个阶段 |
| **N-7** | 不修改系统 DNS 配置时的网内域名解析（MagicDNS 类） | 无 TUN 时对系统不透明；设备名寻址走 `cmesh` 子命令（R-4.4） |
| **N-8** | 跨身份互通与跨身份 ACL | 一个身份就是一个信任边界（§1.3），不做身份间联邦 |
| **N-9** | 「全网均不可达」时保证通信 | 对称 NAT × 对称 NAT 且网内无可达中转节点时无解；通信前提是 C-3 的「至少一个节点可达」 |
| **N-10** | 无 root/`CAP_NET_BIND_SERVICE` 时本地监听 <1024 端口 | 内核限制；转发到本机低位端口（22/53/80）需特权或调整 `ip_unprivileged_port_start` |

### 4.2 性能门槛

| 编号 | 指标 | 门槛 | 说明 |
|---|---|---|---|
| **P-1** | 同机房两台直连的往返延迟 | **< 5 ms**（p95） | 打洞直连，不经中转 |
| **P-2** | 同机房经中转的往返延迟 | < 20 ms（p95） | 多一跳 |
| **P-3** | 直连大文件吞吐 | **≥ 200 MiB/s** | 相对阶段 1 的 515 MiB/s 打余量 |
| **P-4** | 经中转的大文件吞吐（**能力门槛**） | ≥ 50 MiB/s | 中转节点是瓶颈。**这一条量的是「中转这条路径本身能跑多快」，不是「默认配置下能跑多快」** —— 见下面 P-4 与 P-7 的关系 |
| **P-5** | 拓扑收敛：**异常掉线**（kill -9 / 断网） | < 10 s | 由传输层断连检测保证，不是心跳轮询 |
| **P-5b** | 拓扑收敛：**优雅下线**（主动退出） | < 3 s | 显式 LEAVE 广播 |（✅ 已实现：LEAVE 走 announce 的签名变体，真实公网实测收敛 **1128 ms**（预算 3s）；LEAVE 丢失时降级到断开检测仍收敛（单测 957 µs））|
| **P-6** | 单节点 20 台设备时的 RSS | < 100 MiB | |
| **P-7** | 中转配额（**默认限速**） | 单节点默认 ≤ 50 MiB/s、≤ 20 条流 | 防止被当免费跳板。**这一条管的是「默认给多少」** |

#### ★ P-4 与 P-7 的关系：它们管的不是同一件事（Round 104 裁定）

**这两条并排写着，但从前没有人说过它们为什么能同时成立 —— 于是它们看起来是矛盾的**
（P-4 要求 ≥ 50 MiB/s，P-7 要求 ≤ 50 MiB/s）。

**它们管的是两件事**：

| | 管什么 | 谁改它 |
|---|---|---|
| **P-7** | **默认**给一个节点多少带宽（防止有人把中转当免费跳板） | 运维改配置 |
| **P-4** | 中转这条**路径**本身能跑多快（能力是否够用） | 改不了，只能测 |

**⇒ 一个节点按默认配置跑，吞吐恰好在 50 MiB/s 附近 —— 那正是 P-4 的门槛，
也正是 P-7 的上限。两者在边界上相遇，而不是互相否定。**
**「默认上限」与「能力门槛」取同一个数字，是因为门槛定得足够低，
而配额定得刚好够一个正常负载用。**

**★ 实测把这条关系摆出来了**（Round 92 / Round 104，本地回环，10 核）：

| 配额 | 实测持续吞吐 | 说明 |
|---|---|---|
| 50 MiB/s（默认） | **55.61** | **算术预测 55.41 —— 差 0.4%** ⇒ 配额精确地钉住了速率 |
| 100 MiB/s | **124.77** | 算术预测 124.27 —— 差 0.4% |
| 200 MiB/s | 138.61 | **路径封顶了**（配额再大也没用） |
| 400 / 1000 MiB/s | 138.00 / 134.93 | 同上（**5 倍配额、1.02 倍速率**） |

**⇒ P-7 的默认 50 MiB/s 让默认部署正好达到 P-4 的门槛；
而把配额调高（运维的选择）能到 ~138 MiB/s，远高于门槛。**

**★ 缺口照抄**：**以上全是本地回环**。**真 WAN 上拥有天花板的会是 RTT 而不是 syscall 路径**
（Round 104 的性能线），**所以绝对值不能迁移**。

#### ★ 性能门槛的性质与断言纪律

**按 `docs/CONVENTIONS.md` 的 T-2.4/T-2.5/T-2.6，墙钟绝对阈值不做硬断言**
（并行跑包时 CPU 争抢能让健康链路掉到 4 MiB/s，硬断言只会变成随机红的测试）。
**⇒ P-1 / P-2 / P-3 / P-4 / P-5 / P-6 属于「实测门」而不是「CI 门」**，
**它们由测量与人工判定守，不由 `go test` 守。**
**其中 P-5b（3 秒收敛）有硬断言**（`internal/discovery/leave_test.go`，因为收敛时间受负载影响小），
**P-7 的「流数」有硬断言**（第 21 条流被拒），
**而 P-7 的「速率」只断言性质不断言数字**（断言的是「配额是速率而不是文件大小上限」）。

### 4.3 兼容性

| 编号 | 要求 |
|---|---|
| **C-1** | 无界面的 CLI / 锚点保持单二进制静态链接，无 CGO、无运行时依赖；R-6.5 图形客户端单独打包，可使用系统 WebView 与原生桥，不把桌面运行库带入容器版本 |
| **C-2** | CLI / 锚点支持 linux/amd64、linux/arm64、darwin/amd64、darwin/arm64、windows/amd64；图形客户端的平台范围和验收另见 R-6.5 |

| **C-4** | 协议向后兼容：新增帧类型不升版本号，靠 `caps` 协商 |
| **C-5** | 传输必须能穿过仅允许 HTTP(S)/WebSocket 出站的环境（代理、CDN 前置）——U3 受限容器场景的准入条件 |

### 4.4 运维要求

| 编号 | 要求 |
|---|---|
| **O-1** | 节点无状态：本地只存身份密钥与配置，不存路由表持久化 |
| **O-2** | 任一节点可重启，不影响其他节点之间的连通 |
| **O-3** | 加入网络只需一个邀请（不是一串 IP 列表） |
| **O-4** | 一条命令启动，失败时给出可操作的错误信息 |
| **O-5** | 邀请是一个可传递的单串（载体明确），有默认有效期、一次性、可撤销语义；过期/已用/已撤销的邀请报可操作错误 |
| **O-6** | 自举零配置：邀请自带发现节点种子端点；首台设备默认成为发现节点；种子全部不可达时报可操作错误 |
| **O-7** | 本地监听端口被占用时报可操作错误，并给出替代端口建议 |
| **O-8** | `cmesh doctor`：报告 TUN/出站/端口等环境能力（复用 internal/probe），用于失败诊断（P2） |

## 5. 验收标准

### 5.1 阶段 2 验收（组网）

| 项 | 标准 |
|---|---|
| 三节点直连 | 三台同机房机器，任意两台 `cmesh mesh ping`（自定义 RTT）< 5 ms（p95，P-1） |
| 多设备身份 | 同一身份下 4 台设备互相可见，`cmesh status` 全部列出（依赖 R-2.3，P0） |
| 中转 | 人为阻断 A↔C 直连，A→C 自动经 B 中转，仍可通（P0 只要求确定性选中首个可用中转；择优选路归 R-3.3） |
| 中转开关 | 未开启中转的节点不承载任何转发（与普通成员无区别）；开启前反向拨号检测不通过则拒绝开启并给出原因；关闭立即拆掉承载中的流；面板 / 参数 / 信号三个入口状态一致 |
| 中转延迟 | 强制走中转的 RTT < 20 ms（p95，P-2） |
| 大文件 | 直连 ≥ 200 MiB/s，经中转 ≥ 50 MiB/s，SHA-256 一致 |
| 异常掉线收敛 | `kill -9` 一台节点，其余 ≤10 s 感知并更新拓扑（P-5；与优雅下线 P-5b 分测） |
| 非成员隔离 | 无成员凭证的注册/查询/订阅请求逐端点全部被拒（R-2.4） |
| 撤销 | 撤销一台设备的身份，其活跃会话在一个推送往返内被销毁且无法重连，其他设备不受影响（可判定形式：撤销广播后 ≤ 30 s 内旧会话拆毁、新握手被拒；机制是发现节点推送，30 s 是测试断言的宽限上限，不是等心跳或重连才发现） |
| 端到端加密 | 中转节点抓包看不到明文 |
| 配额 | 单节点被持续转发时，吞吐 ≤ 50 MiB/s、流数 ≤ 20（P-7），且自身业务不受影响 |
| 资源 | 单节点承载 20 台设备在线，RSS < 100 MiB（P-6） |

### 5.2 每轮迭代的验收门槛

见 [`CONVENTIONS.md`](CONVENTIONS.md) §6 检查清单。核心五条：

1. `gofmt` / `vet` / `build` 全干净
2. `go test ./... -race` 全绿，**连续 10 轮不偶发失败**
3. e2e 既有断言全过（含阶段 1 冻结的部分）
4. 性能门槛不回退（**A/B 同刻对照**，不用历史最好值当基线）
5. 新测试能证明「改坏了会红」
