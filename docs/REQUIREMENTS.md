## 1. 问题定义

### 1.1 一句话

让两台**只能出站联网**的机器之间，安全地传文件、传消息、转发端口。

### 1.2 这不是什么

先把边界钉死，否则需求会无限膨胀：

| 不是 | 为什么 |
|---|---|
| 不是 VPN | 无 `CAP_NET_ADMIN` 时做不了 L3；能做的那部分见 R-3.4 |
| 不是组网方案（Tailscale/EasyTier 那类） | 它们的核心是虚拟网卡；我们的核心是「不需要虚拟网卡也能干活」 |
| 不是文件同步工具 | Syncthing 那类是双向持续同步；我们是一次性传输 + 断点续传 |
| 不是跳板机管理平台 | 没有堡垒机、审计录像、会话回放 |

### 1.3 为什么现有工具不够

| 工具 | 卡在哪 |
|---|---|
| `scp` / `rsync` | 需要一端可达（入站端口或公网 IP） |
| `croc` | 需要公共 relay，且中继能看到房间码；无端口转发 |
| Tailscale / EasyTier | 需要 TUN 设备 + `CAP_NET_ADMIN`；在受限容器里起不来 |
| SSH 反向隧道 | 需要一台双方都能连的跳板机，且要维护密钥 |

**共同缺口**：在「零特权 + 零入站端口」的容器里，没有既安全又能转发端口的工具。

## 2. 用户与场景

### 2.1 主要用户（按优先级）

| 编号 | 用户 | 他们的处境 | 他们现在怎么做 |
|---|---|---|---|
| **U1** | 在受限容器里干活的开发者 | 云函数/K8s Pod/托管容器，无 root、无入站端口，只有出站 | 把文件传到对象存储再拉，或干脆放弃 |
| **U2** | 运维/值班 | 内网服务只在跳板机本地可达 | 一层层 SSH 跳，或开临时隧道 |
| **U3** | 演示/协作场景 | 两台机器临时要通，不想配 VPN | 临时开公网端口（有安全风险） |

### 2.2 核心场景

**S1 — 从受限容器里取文件**（U1）
容器里跑完任务生成了结果，要拿回本地。容器没有公网 IP、没有入站端口。

**S2 — 连到只有内网可达的数据库**（U2）
数据库监听 `127.0.0.1:5432`，只在那台机器上可达。要在本地用 `psql` 连。

**S3 — 让受限容器对外提供临时服务**（U1/U3）
容器里起了个调试用的 HTTP 服务，想让同事从外面访问，但容器没有入站端口。

**S4 — 两台都在 NAT 后互传大文件**（U1）
两端都只有出站能力，要传几百 MB 到几 GB 的文件。

### 2.3 明确不考虑的场景

- 需要 `ping` 通对方（见 R-4 硬边界）
- 长时间运行的站点对站点互联（那是 SD-WAN 产品的事）
- 多租户隔离（单用户工具，不做账号体系）

## 3. 功能需求

优先级：**P0** = 没有它产品不成立；**P1** = 核心场景需要；**P2** = 有用但可延后。

### 3.1 传输（阶段 1，已实现）

| 编号 | 需求 | 优先级 | 状态 |
|---|---|---|---|
| **R-1.1** | 两端只需出站连接到一台中继即可传文件 | P0 | ✅ |
| **R-1.2** | 大文件断点续传：中断后从已收字节处继续，不重传 | P0 | ✅ |
| **R-1.3** | 传完校验 SHA-256，不一致不落盘为正式文件 | P0 | ✅ |
| **R-1.4** | 目录传输：对端看到目录树，不是 tar 包 | P1 | ✅ |
| **R-1.5** | 双向并发：一边发一边收 | P1 | ✅ |
| **R-1.6** | 多中继：按列表故障切换 | P1 | ✅ |
| **R-1.7** | 自动重连：中继或网络断开后自动恢复会话 | P0 | ✅ |
| **R-1.8** | 零字节文件可传输 | P1 | ✅ |
| **R-1.9** | 覆盖保护：默认拒绝覆盖已有文件，需显式 `--force` | P0 | ✅ |

### 3.2 端口转发（阶段 1，已实现）

| 编号 | 需求 | 优先级 | 状态 |
|---|---|---|---|
| **R-2.1** | `-L`：本地监听 → 对端拨号（等价 `ssh -L`） | P0 | ✅ |
| **R-2.2** | `-R`：请求对端监听 → 回连本地（等价 `ssh -R`） | P0 | ✅ |
| **R-2.3** | 一条隧道承载多条转发规则 | P1 | ✅ |
| **R-2.4** | 半关闭传播：HTTP/1.0 这类先关写端再等响应的协议必须工作 | P0 | ✅ |
| **R-2.5** | 服务端先说话：SMTP banner 这类协议必须工作 | P0 | ✅ |
| **R-2.6** | 转发与文件传输共用一条连接 | P2 | 部分（库已支持，CLI 未接线） |

### 3.3 安全（阶段 1，已实现）

| 编号 | 需求 | 优先级 | 状态 |
|---|---|---|---|
| **R-3.1** | 中继看不到明文 | P0 | ✅ |
| **R-3.2** | 中继看不到口令（房间号是口令的派生值） | P0 | ✅ |
| **R-3.3** | 能检测主动中继：两端可核对短认证串（SAS） | P0 | ✅ |
| **R-3.4** | 转发默认拒绝一切，需显式授权目标 | P0 | ✅ |
| **R-3.5** | `-R` 有独立的端口白名单（比 `-L` 风险高一个量级） | P0 | ✅ |
| **R-3.6** | 策略检查必须在拨号之前（否则成为端口扫描器） | P0 | ✅ |
| **R-3.7** | 建流速率限制（并发限制不能替代速率限制） | P1 | ✅ |
| **R-3.8** | 接收端文件名校验：路径穿越、保留字、隐藏文件 | P0 | ✅ |
| **R-3.9** | 接收端磁盘空间预检 | P1 | ✅（Unix；Windows 降级为不检查） |

## 4. 非功能需求

### 4.1 硬边界（做不到的，明确写出来）

| 编号 | 做不到 | 原因 |
|---|---|---|
| **N-1** | 无 TUN 时 `ping` 通对端 | 内核没有接口承载该路由，无 workaround |
| **N-2** | 无 TUN 时 `ssh user@100.64.0.5` 直连 | 同上，必须走代理参数 |
| **N-3** | 让不感知代理的进程透明走隧道 | `LD_PRELOAD` 只影响本进程及子进程 |
| **N-4** | SCTP / 任意 IP 协议 | 用户态 netstack 不实现 |
| **N-5** | 中继之间链式转发 | 需要节点间隧道 + 环路处理，复杂度相当于再造一层协议 |

### 4.2 性能门槛

| 编号 | 指标 | 门槛 | 依据 |
|---|---|---|---|
| **P-1** | 512 MiB 回环文件传输 | ≥ 485 MiB/s | 相对 539 MiB/s 基线的 10% 退化上限 |
| **P-2** | 单流 `-L` 转发吞吐 | ≥ 200 MiB/s | 库层实测 1957–2748 MiB/s，全栈打折 |
| **P-3** | 跨公网吞吐 | ≥ 现有 11–12 MiB/s 的 80% | |
| **P-4** | 100 条活跃流转发时 RSS | < 80 MiB | |
| **P-5** | 中继空载 RSS | < 20 MiB | 实测 8.5 MB |

### 4.3 兼容性

| 编号 | 要求 |
|---|---|
| **C-1** | 单二进制静态链接，无 CGO、无运行时依赖 |
| **C-2** | 支持 linux/amd64、linux/arm64、darwin/amd64、darwin/arm64、windows/amd64 |
| **C-3** | 中继只建议部署在 Linux（需要守护进程管理） |
| **C-4** | 协议向后兼容：新增帧类型不升版本号，靠 `caps` 协商 |

### 4.4 运维要求

| 编号 | 要求 |
|---|---|
| **O-1** | 中继无状态：不落盘、不记录口令，重启不丢数据（本来就没有） |
| **O-2** | 中继只需一个入站 TCP 端口 |
| **O-3** | 客户端零入站端口 |
| **O-4** | 一条命令启动，失败时给出可操作的错误信息 |

## 5. 验收标准

### 5.1 阶段 1 验收（已完成）

| 项 | 标准 | 实测 |
|---|---|---|
| 单元测试 | 全绿，含 `-race` | 237 个函数，12/12 包 |
| e2e | 既有断言不退化 | 35/35（quick）、37/37（含 256 MiB） |
| 吞吐 | ≥ 485 MiB/s | 515 / 615 / 594 MiB/s |
| `-L` 端到端 | 真实进程 + 真实服务 | 本地 15555 → 云端 19999，字节一致 |
| `-R` 端到端 | 同上 | 应用连 hoster 端口，回连 requester 本地服务 |
| 跨机 | 跨公网传输 | macOS → 云主机 5 MiB，SHA-256 一致 |
| 受限容器 | 只能出站的容器能当客户端 | Cloud Studio 容器 3 MB 传输成功 |
| 策略 | 拒绝时目标零字节到达 | dialer 调用次数 0 |

### 5.2 每轮迭代的验收门槛

任何改动合入前必须满足（详见 [`CONVENTIONS.md`](CONVENTIONS.md)）：

1. `go build ./...`、`go vet ./...`、`gofmt -l .` 全干净
2. `go test ./... -race` 全绿，且**连续 10 轮不偶发失败**
3. e2e 既有断言全过
4. 性能门槛不回退（A/B 同刻对照，不用历史最好值当基线）
5. 新功能有对应测试，且测试能证明「改坏了会红」
