# 需求清单（Requirements）

> 三层文档第一层。顺序 **需求 → 设计 → 技术**：
> 本文说「要解决谁的什么问题、做到什么算成功」；
> [`DESIGN.md`](DESIGN.md) 说「用什么结构解决」；
> [`architecture/`](architecture/) 与 [`research/`](research/) 说「具体怎么做、为什么」。
>
> 修改本文必须走 [`CONVENTIONS.md`](CONVENTIONS.md) 的变更流程：编号一旦分配不再复用。

**版本**：R2（2026-10-23）— **重大修订**：从「两台机器之间的传输工具」改为「N 台机器组网」
**状态**：阶段 1 冻结；阶段 2（组网）设计中，未实现。

> **R1 → R2 修订说明**
> R1 把本项目定义为「传文件 + 转发端口的工具」，场景都是**两台机器**之间。
> 实际需求是 **组网**：N 台机器、同一身份多设备、任意两台可直达、每台都是节点。
> 这不是范围扩大，是产品定义变了。R1 的传输与转发能力在组网里仍然有用（见 §3.5），
> 但它们是**能力**，不是**产品**。

## 1. 问题定义

### 1.1 一句话

把散落在各处的机器（云服务器、受限容器、家里的机器、笔记本）连成一张**自己的网**：
同一个身份下的设备互相可见、可直接通信、可互传大文件，不依赖任何中心服务，
不需要公网 IP，不需要 root。

### 1.2 与 R1 的关键差异

| 维度 | R1（旧） | R2（本版） |
|---|---|---|
| 拓扑 | 两台，一对一配对 | **N 台，任意两台** |
| 身份 | 一个临时 code，用完即弃 | **长期身份（密钥对），多设备共存** |
| 中继 | 必需的专用服务器 | **节点自己就能当中转**（可选加速） |
| 数据路径 | 全部经中继 | **优先直连，失败才经其他节点中转** |
| 用户心智 | 「传个文件」 | 「我的设备组成一张网」 |

### 1.3 这不是什么

| 不是 | 为什么 |
|---|---|
| 不是 VPN | 无 `CAP_NET_ADMIN` 时做不了透明 L3；能做的那部分见 R-5.2 |
| 不是 Tailscale 的复刻 | 不实现 WireGuard、不做内核态；我们是用户态、零特权的替代路线 |
| 不是文件同步 | 不做持续双向同步、不做冲突合并 |
| 不是多租户 SaaS | 一个身份就是一个人/一个团队，不做账号体系与计费 |

## 2. 用户与场景

### 2.1 用户

| 编号 | 用户 | 处境 |
|---|---|---|
| **U1** | 个人开发者 | 有 2–10 台机器：笔记本、几台云服务器、几个受限容器。要它们互相通 |
| **U2** | 小团队 | 每人多台设备，团队内要共享某些服务（数据库、内部 API） |
| **U3** | 受限环境使用者 | K8s Pod / 云函数 / 托管容器：无 root、无入站端口、无 TUN |

**U1 是首要目标。** 先让一个人自己的 5 台机器连成网，比先支持 500 台更有价值。

### 2.2 核心场景

**S1 — 我的设备互相看见**
笔记本、云服务器 A、云服务器 B、家里的 NAS 都登同一个身份。任意一台上执行
`cmesh status`，能看到其余三台在线、各自的地址与延迟。

**S2 — 从笔记本直接操作云服务器上的服务**
云服务器上的数据库只听 `127.0.0.1:5432`。笔记本上 `cmesh forward` 或直接
`cmesh dial db` 就能连，**不需要知道那台机器的公网 IP**。

**S3 — 两台设备互传大文件**
笔记本 → NAS，10 GB。要快（不慢于 scp 的合理比例），中断可续传。

**S4 — 两台都在 NAT 后**
笔记本在家里、服务器在办公室内网，两边都没公网 IP。要么打洞直连，
要么经第三台（有公网的那台云服务器）中转。

**S5 — 受限容器加入网**
K8s Pod 里跑一个 agent，无 root、无入站端口，但能出站。它要能被网内其他设备访问。

### 2.3 明确不考虑

- 需要 `ping` 通对方（见 §4.1 硬边界）
- 数百台以上的规模（先做到几十台稳定）
- 跨组织的信任联邦（一个身份就是信任边界）

## 3. 功能需求

优先级：**P0** = 没有它组网不成立；**P1** = 核心场景需要；**P2** = 有用可延后。

### 3.1 身份（阶段 2，核心）

| 编号 | 需求 | 优先级 | 状态 |
|---|---|---|---|
| **R-1.1** | 每台设备持有长期密钥对，公钥即身份 | P0 | ❌ |
| **R-1.2** | 同一身份下多设备共存，设备间互相认证 | P0 | ❌ |
| **R-1.3** | 设备可单独撤销（一台丢了不影响其他） | P0 | ❌ |
| **R-1.4** | 身份密钥加密存储在本地，不依赖任何服务器 | P0 | ❌ |
| **R-1.5** | 加入网络需要显式授权（不能靠猜口令进网） | P0 | ❌ |
| **R-1.6** | 设备名、标签等元数据可读可改 | P1 | ❌ |

### 3.2 发现与拓扑（阶段 2，核心）

| 编号 | 需求 | 优先级 | 状态 |
|---|---|---|---|
| **R-2.1** | 节点自动发现彼此，无需手工配置 IP 列表 | P0 | ❌ |
| **R-2.2** | 拓扑变化（上线/下线/换 IP）在秒级收敛 | P0 | ❌ |
| **R-2.3** | 任一节点可查询全网成员与连通状态 | P1 | ❌ |
| **R-2.4** | 发现层不暴露给非成员：外部无法枚举网内设备 | P0 | ❌ |
| **R-2.5** | 无中心也能工作：至少一个节点可达即可（可以是任意成员） | P1 | ❌ |

### 3.3 连接与路由（阶段 2，核心）

| 编号 | 需求 | 优先级 | 状态 |
|---|---|---|---|
| **R-3.1** | 优先直连：能打洞就走 P2P，不经任何中转 | P0 | 部分（打洞已实现，未接入组网） |
| **R-3.2** | 直连失败时，经网内其他节点中转（**不是**专用中继） | P0 | ❌ |
| **R-3.3** | 中转路径自动选择，用户不需要指定走哪台 | P1 | ❌ |
| **R-3.4** | 路径可切换：直连断了自动退回中转，恢复后自动切回 | P1 | ❌ |
| **R-3.5** | 中转节点不知道自己在转发谁的数据（端到端加密） | P0 | ❌ |
| **R-3.6** | 转发有配额：单节点被当跳板时有上限，不拖垮自己 | P1 | ❌ |

### 3.4 通信能力（阶段 2）

| 编号 | 需求 | 优先级 | 状态 |
|---|---|---|---|
| **R-4.1** | 任意两台之间可发消息，低延迟（同机房 <10 ms） | P0 | 部分（仅两人配对） |
| **R-4.2** | 任意两台之间可传文件，支持大文件与断点续传 | P0 | ✅ 能力已有 |
| **R-4.3** | 一条连接承载多路复用（消息 + 文件 + 转发共存） | P0 | ✅ 已有 |
| **R-4.4** | 按设备名寻址，不用记 IP | P1 | ❌ |
| **R-4.5** | 任意两台之间可开端口转发（把某台的服务暴露给网内） | P1 | ✅ 能力已有 |

### 3.5 已有能力（阶段 1，冻结但保留）

阶段 1 交付的这些能力在组网里**继续有效**，只是暂时不继续投入：

| 编号 | 能力 | 状态 | 在组网里的角色 |
|---|---|---|---|
| **R-5.1** | SPAKE2 握手 + AES-256-GCM | ✅ | 可复用为会话加密（长期身份另需密钥交换） |
| **R-5.2** | 记录泵 + yamux 多路复用 | ✅ | 直接复用：组网也是多流复用 |
| **R-5.3** | 打洞 + QUIC 直连 | ✅ | **组网的核心**：直连层 |
| **R-5.4** | `-L` / `-R` 端口转发 | ✅ | 组网里的一个能力（R-4.5） |
| **R-5.5** | 文件传输 + 断点续传 + 校验 | ✅ | 组网里的一个能力（R-4.2） |
| **R-5.6** | 中继配对 + 限流 + 状态看板 | ✅ | 可演化为「发现节点」 |

**冻结的含义**：不再新增功能、不再优化，但**不删除**、不破坏。
组网需要它们时直接复用。

### 3.6 界面（阶段 3，后置）

| 编号 | 需求 | 优先级 | 状态 |
|---|---|---|---|
| **R-6.1** | 看到网内所有设备与在线状态 | P2 | ❌ |
| **R-6.2** | 看到拓扑：谁和谁直连、谁经谁中转 | P2 | ❌ |
| **R-6.3** | 看到每台设备的实测延迟与带宽 | P2 | ❌ |
| **R-6.4** | 一键发起传输 / 一键建转发 | P3 | ❌ |

**界面后置的理由**：拓扑与带宽数据来自底层，底层没通时界面只能造假数据。

## 4. 非功能需求

### 4.1 硬边界（做不到的，明确写出来）

| 编号 | 做不到 | 原因 |
|---|---|---|
| **N-1** | 无 TUN 时 `ping` 通对端 | 内核没有接口承载该路由，无 workaround |
| **N-2** | 无 TUN 时 `ssh user@100.64.0.5` 直连 | 同上，必须走 `cmesh` 子命令或代理参数 |
| **N-3** | 让不感知代理的进程透明走网 | `LD_PRELOAD` 只影响本进程及子进程 |
| **N-4** | 对称 NAT × 对称 NAT 之间直连 | 无解，必须经第三方中转（R-3.2 覆盖） |
| **N-5** | SCTP / 任意 IP 协议 | 用户态 netstack 不实现 |
| **N-6** | 数百台规模的全局路由收敛 | 先做几十台；规模上去需要 DHT 或分层，是另一个阶段 |

### 4.2 性能门槛

| 编号 | 指标 | 门槛 | 说明 |
|---|---|---|---|
| **P-1** | 同机房两台直连的往返延迟 | **< 5 ms**（p95） | 打洞直连，不经中转 |
| **P-2** | 同机房经中转的往返延迟 | < 20 ms（p95） | 多一跳 |
| **P-3** | 直连大文件吞吐 | **≥ 200 MiB/s** | 相对阶段 1 的 515 MiB/s 打余量 |
| **P-4** | 经中转的大文件吞吐 | ≥ 50 MiB/s | 中转节点是瓶颈 |
| **P-5** | 拓扑变化收敛时间 | < 10 s | 节点下线后其他节点察觉 |
| **P-6** | 单节点 20 台设备时的 RSS | < 100 MiB | |
| **P-7** | 中转配额 | 单节点默认 ≤ 50 MiB/s、≤ 20 条流 | 防止被当免费跳板 |

### 4.3 兼容性

| 编号 | 要求 |
|---|---|
| **C-1** | 单二进制静态链接，无 CGO、无运行时依赖 |
| **C-2** | linux/amd64、linux/arm64、darwin/amd64、darwin/arm64、windows/amd64 |
| **C-3** | 客户端零入站端口；至少一个节点可达即可（不要求固定某台） |
| **C-4** | 协议向后兼容：新增帧类型不升版本号，靠 `caps` 协商 |

### 4.4 运维要求

| 编号 | 要求 |
|---|---|
| **O-1** | 节点无状态：本地只存身份密钥与配置，不存路由表持久化 |
| **O-2** | 任一节点可重启，不影响其他节点之间的连通 |
| **O-3** | 加入网络只需一个邀请（不是一串 IP 列表） |
| **O-4** | 一条命令启动，失败时给出可操作的错误信息 |

## 5. 验收标准

### 5.1 阶段 2 验收（组网，未开始）

| 项 | 标准 |
|---|---|
| 三节点直连 | 三台同机房机器，任意两台 `cmesh ping`（自定义 RTT）< 5 ms |
| 多设备身份 | 同一身份下 4 台设备互相可见，`cmesh status` 全部列出 |
| 中转 | 人为阻断 A↔C 直连，A→C 自动经 B 中转，仍可通 |
| 大文件 | 直连 ≥ 200 MiB/s，经中转 ≥ 50 MiB/s，SHA-256 一致 |
| 收敛 | 杀掉一个节点，其余节点 10 s 内感知并更新拓扑 |
| 撤销 | 撤销一台设备的身份，该设备立即被拒绝，其他设备不受影响 |
| 端到端加密 | 中转节点抓包看不到明文 |
| 配额 | 单节点被持续转发时，吞吐被限制在配额内且自身业务不受影响 |

### 5.2 每轮迭代的验收门槛

见 [`CONVENTIONS.md`](CONVENTIONS.md) §6 检查清单。核心五条：

1. `gofmt` / `vet` / `build` 全干净
2. `go test ./... -race` 全绿，**连续 10 轮不偶发失败**
3. e2e 既有断言全过（含阶段 1 冻结的部分）
4. 性能门槛不回退（**A/B 同刻对照**，不用历史最好值当基线）
5. 新测试能证明「改坏了会红」
