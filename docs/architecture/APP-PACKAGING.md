# 跨平台应用包装与原型改造

日期：2026-11-12。状态：设计已确定，尚未交付 App 安装包。
需求：R-6.1–R-6.5；约束：R-2.4、C-1、C-2、C-5。

## 1. 产品边界

用户已认可 `design-prototypes/aistudio-v1/` 的视觉、交互和整体展示。
改造保留这些成果，调整数据来源、引擎调用、平台能力和打包方式。归档原型保留为
设计对照；生产实现另建目录，避免把演示页面误当成已完成的产品。

应用包装是当前主开发线之一。原先 M4 / M5 / M6 的日期不能解释为届时五个平台都
已验收；平台发布必须以各自的安装、连接、传输和恢复证据为准。

## 2. 技术选择

| 形态 | 实现 | 交付与运行约束 |
|---|---|---|
| 容器 / 服务器 | 现有 Go CLI、锚点和传输引擎 | 保持 C-1：无 CGO、单二进制，无 GUI 运行库 |
| 锚点轻量面板 | 小型静态 HTML/CSS/JS，由 Go 嵌入并服务 | 同源访问、运行时不依赖 CDN；仅展示已获授权的网络数据 |
| Windows / macOS / Linux 桌面 | Wails + React / TypeScript + Go 引擎 | 分平台构建和安装；系统 WebView、Linux 图形库等依赖明确记录 |
| Android / iOS | 原生宿主 + gomobile 绑定的 Go 引擎；可适配视图复用 React | 先验证桥接与生命周期，再定完整 UI 复用范围；不把 Wails 当作移动方案 |

React 和 Vite 保留为界面与构建工具。生产产物是离线静态资源；用户不安装 Node.js，
不在设备上运行 Vite 开发服务器。Wails 的具体版本在桌面样机阶段锁定，按三个系统
验证后才加入发布矩阵。

浏览器面板连接已有引擎，不自行充当持有设备身份、监听 QUIC 的组网节点。

## 3. 代码边界

建议的新代码布局（均为规划，尚未创建实现）：

- `internal/app/`：收拢设备会话的启动、停止、状态查询、事件订阅和取消；复用
  `identity`、`discovery`、`mesh` 等包，不复制协议实现。
- `ui/`：产品界面、共享领域类型和视图状态。生产数据通过显式接口注入。
- `apps/desktop/`：Wails 生命周期、原生文件选择、系统通知与平台打包。
- `apps/mobile/`：Go 导出接口与 Android / iOS 宿主验证；只暴露绑定可支持的简单类型。
- 轻量面板继续位于 Go 服务的嵌入资源中，不强迫其引入桌面完整应用的依赖。

前端调用的是稳定的业务操作，例如读取成员视图、加入网络、发起传输、查询任务和
取消任务。平台适配器负责把操作转为 Wails 绑定、受认证的本地 HTTP 接口或移动原生桥。
不通过调用 CLI 再解析终端文本来复用引擎。

Go 引擎拥有设备身份、会话与传输任务；界面拥有选中设备、筛选、布局等展示状态。
关闭窗口是否退出节点需要明确设置与提示；桌面托盘存活、系统后台服务和移动后台
是不同能力，不能用“窗口隐藏了”代替后台能力验收。

## 4. 从演示变为可用产品

1. 保留原型的视觉变量、组件和交互关系，移除生产入口对模拟场景的依赖。
2. 将网络、成员、任务、路径、测量值整理为领域类型。成员在名册中、发现节点报告
   在线、端点已公告、实际拨号成功是不同状态，不能压成一个“连接成功”。
3. 数据接口返回时间、来源与能力范围。断线时保留最后有效快照并标记过期；未采集
   的延迟、吞吐、地理位置显示未知，不生成演示数值填空。
4. 文件选择交给系统；文件内容由 Go / 原生层流式读取与传输。前端只拿任务 ID、
   进度和结果，不把大文件转为 base64 穿过 JavaScript 桥。
5. 设备私钥留在引擎和平台安全存储边界内，不注入页面、前端环境变量或 localStorage。
   桌面 IPC 按业务操作限定；HTTP/WS 接口即使只监听回环也须有会话认证和来源校验。
6. 3D 视图按需加载，提供 2D 降级与减少动画选项。手机重新排版并支持触控，不把
   桌面固定宽度布局直接缩放。
7. 归档原型里的生成工具 SDK、调试开关和环境占位符逐项核查。只有实际产品能力
   需要且有明确调用方的依赖才进入生产构建。

## 5. 平台差异要实际验收

| 平台 | 必验能力 |
|---|---|
| Windows | WebView2 前提、安装/卸载、路径与权限、托盘退出语义、休眠恢复 |
| macOS | 应用包签名/分发方式、钥匙串适配、文件授权、休眠恢复 |
| Linux 桌面 | 所选发行版的 WebKitGTK 等依赖、安装/卸载、显示会话与无头模式隔离 |
| Android | 文件选择与 URI 访问、前台服务和通知、后台限制、网络切换、进程重建 |
| iOS | 文件沙箱/分享、Keychain、签名与分发、前后台切换、系统挂起后的恢复 |

移动端首版以打开应用时可使用为基线。特别是 iOS，普通应用不能承诺锁屏后无限期
保持 mesh 在线；后台连续传输和常驻节点能力要单独做真机验证，若需要专有系统能力
再评估，不能把操作系统限制包装成已支持。

## 6. 交付顺序与验收门

| 批次 | 可验收结果 | 完成证据 |
|---|---|---|
| A：引擎质量与业务接口 | 恢复可见性、传输本地错误可诊断；抽取应用生命周期接口 | 缺陷红绿对照、完整 Go CI、真实三进程测试 |
| B：真实数据界面 | 原型中的设备与网络视图接真实数据，演示源独立 | 无外网资源可打开；在线/离线/恢复、空状态与过期快照浏览器实测 |
| C：桌面首包 | Windows、macOS、Linux 分别能安装、入网、传文件、退出与恢复 | 每个平台记录 OS / 架构 / 包哈希 / 测试结果；交叉编译不算运行验收 |
| D：移动验证与首包 | Go 绑定、触控布局、文件权限、生命周期 | Android 和 iOS 真机各跑通一条传输链路，再扩充完整功能 |
| E：发布 | 安装入口、更新策略、迁移/回滚、许可证与第三方声明齐全 | 完整本地 CI + 平台矩阵 + 成品验收后执行发布流程 |

每个批次都交付可检查的代码或产物。代码、测试、已推送、已发布分开记账；不存在
的平台产物不能因为架构已确定而标记完成。main 仍只承接成品发布，按既定放行规则执行。
