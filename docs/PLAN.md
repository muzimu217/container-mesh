# container-mesh 项目总计划（PLAN）

> **本文是项目的唯一计划文档**：现状、里程碑、任务表、每日节奏、待裁定，全在这里。
> **编号只有一套**：里程碑用 `M`，任务用 `M<里程碑>-<序号>`（如 `M4-7`、`M5-12`）。
> 需求与设计是**只读基线**（见 §6）；**完成情况与留痕只写本文**。

**版本**：V1（2026-11-24 重置）
**分支**：`develop` @ `5622e5b`（本地，领先远端 1 笔）· 远端 `origin/develop` @ `bb1e225`（**该 SHA 的 CI 是红的**）· 实测于 2026-11-25 04:20
**产品定义**：把散落在各处的机器连成一张**自己的网**——同一身份下多设备共存、任意两台可直达、
无需公网 IP、**无需 root、无需入站端口、不依赖中心服务**。硬边界：不是 VPN、不做 TUN、不做全局虚拟 IP（`N-1`~`N-10`）。

## 3. 每日 KPI 节奏

### 3.1 第一屏只回答三问

1. **今天推了几笔到 develop？**（当日完成、当日推）

| 字段 | 内容 | 禁止 |
|---|---|---|
| 推送 | 当日 commit 数、远端 tip、CI 状态与 SHA | 只写「CI 绿」不写 SHA |

| 缺口 | 今日新增缺口 + 归属线 | 「本轮无新实验」要写出来 |

### 3.3 节奏与铁律

- **每轮 = 一笔提交 + 红→绿证据 + `ROUND-LOG.md` 一段**，**当日推**（红了先修再推，不推红的）。
- **每周五**里程碑复盘：封口剩余格数 · 阻塞归属 · 口径欠账 · 候选池取舍。
- **铁律一**：封口期间不新增需求编号（新想法只登记到 §8 候选池，不动手）。
- **铁律二**：**没有守卫的能力不显示 PASS**（看板与文档同守）。
- **铁律三**：已提交的 PR 不做 review 噪音改动。
- **铁律四**：**子代理结论先独立复核再采信**（历史上连续三条性能建议被复核推翻）。
- **★ 铁律五：一个阶段封口之前，不动下一个阶段的活。**
  M4 未封口 ⇒ 只做 M4-1~M4-10；**M5 的任务（含标着「M4 溢出」的 M5-1~M5-6）一律不碰**。

  **把 M4 正在复测的那几格搅在一起，就说不清是哪一笔改动动了哪一格**。
  **同理，下一个阶段的活不许写进当前阶段的派单里**：
  「计划里写着 M5-4」不等于「现在该做 M5-4」。

## 9. 交付记账口径（四层分开记账）

项目分成四个交付层级，每层单独记账：

1. **代码实现**：功能是否在源码中完成。
2. **本地验证**：完整门禁和真实本地 / 回环环境是否通过。
3. **远端可复测**：是否已经进入 `origin/develop`，外部 agent 能否拉到同一 SHA。
4. **平台验收**：是否在目标系统安装、运行、入网、传输、退出和恢复。

只有第 3 层之后的结果才派给远程 agent 复测。交叉编译只证明目标二进制可以生成，不等于平台安装包或真机验收完成。

**M4 封口不等于可以正式发布。** 合并到 `main`、对外称「可交付」之前，以下八条缺一不可：

1. 纯出站节点在直连失败时自动走中转
2. `msg` / 文件 / 诊断 / `forward` 用同一套可靠路径模型
3. 撤销后旧会话按要求关闭
4. 文件传输支持中断恢复与完整性校验
5. Linux headless 的安装、升级、回滚、重启恢复在真实系统完成
6. `C-5`（WSS / 443 / 代理环境）有真实证据
7. 文档、README、面板、发布说明使用同一 SHA 与同一状态
8. 所有性能数字带环境、命令、样本——不把回环结果写成公网承诺

在此之前对外只称「预发布 / 开发版」。

## 10. 路线约束与红线（不计入任何里程碑的判定）

这一节是**不管做到哪个里程碑都不许变的东西**。凡标「候选」的只是方案，不等于已实现。
编号沿用产品评审时的 `PM-`，便于回查。

### 核心 profile 不可变（PM-2 · PM-3 · PM-6）

以下属于基础形态，任何 PR 不得改动语义；新增能力只能以可选、可降级的方式叠加：

- 线格式帧头与 magic、协议版本与最低兼容版本字段
- 握手、密钥派生、mTLS 设备证书身份与委派验签
- 成员 / 存活 / 公告三态语义、快照单调版本、凭证与委派记录结构
- 基础流类型与分帧（msg / file / run / ping / forward preamble）
- 端点公告规则：`--endpoint` 是对外可拨地址，`--listen` 是绑定地址，port 0 解析为实际绑定端口

**基础形态不可插拔**（PM-6）：不实现插件加载，不引入动态库、go-plugin、WASM。
前期只预留接口（PM-3）：端口分配、可达性探测、选路决策、连接事件写成 Go interface + 编译期注册表；
握手帧预留 `capabilities` 位图，当前不解析、不启用。

| **PM-1** | 界面是**可选展示层**：核心二进制不含前端资源；第三方界面只依赖带版本号的 `/api/mesh` 契约，不读内部结构 |
