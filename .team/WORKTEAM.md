# 工作团（Real-Agent Workteam）

> 本文把 [`TEAM.md`](../docs/TEAM.md) 的六个**虚拟**专家角色映射到**真实可调用**的外部代理。
> 主代理（ZCode）任**产品经理 + 首席协调**：定需求、理业务逻辑、做交接、验收、合并。
> 外部代理任**评审与实现**——他们的价值不是「多个人」，是**不同模型的盲区不同**。
>
> 所有代理 headless 启动、**零上下文**：每个提示词必须自包含（仓库路径、读什么、产出什么、格式）。

**版本**：W1（2026-10-26）

## 1. 角色分配（谁干什么）

```
        ┌─────────────────────────────────┐
        │  主代理 = 产品经理 + 首席协调      │
        │  （ZCode，本会话）                │
        │  · 需求定义与业务逻辑              │
        │  · 任务拆解与交接                  │
        │  · 代码实现（主写手）              │
        │  · 验收、合并、Round 报告          │
        └───────────────┬─────────────────┘
                        │ headless 委派（Bash）
        ┌───────┬───────┼───────┬───────┬───────┐
        ▼       ▼       ▼       ▼       ▼       ▼
     安全评审  实现评审  QA 评审  机械检查  需求批判  备份
     claude  codebuddy qoder  codearts  opencode  codex
```

| 虚拟角色（TEAM.md） | 真实代理 | 为什么是它 |
|---|---|---|
| ⑤安全专家 | **claude** | 安全推理最细；前一轮外部评审证明它能抓到真实漏洞（撤销即时性缺口） |
| ③开发专家（评审半边） | **codebuddy** | 独立视角读代码结构与抽象；我写码时它当第二双眼睛 |
| ④测试专家（评审半边） | **qoder** | 多模型集合，擅长「这个测试真的测到了吗」 |
| 机械检查 | **codearts** | deepseek-flash 快且便宜，跑文档一致性、编号孤儿这类批量核对 |
| ②需求专家（批判半边） | **opencode** | 读 REQUIREMENTS.md 挑「验收不可判定」「编号断链」 |
| ⑥性能专家 | **claude**（兼） | 性能分析需要推理而非跑分；与安全评审分不同提示词 |
| 备份全岗 | **codex** | 网络恢复后接入，任何一家超时由它顶 |

**分工原则**：我**写**代码，他们**审**代码。同一个人既写又审等于没审——
这是把虚拟六角色升级成真实代理的核心理由。

## 2. 提示词模板

全部在 [`.team/prompts/`](../../.team/prompts/)。共性骨架：

```
你是 <角色>。仓库在 <路径>。先读 <指定文档/代码>。
只回答以下问题，不要修改任何文件：
<问题清单>
输出格式：<格式>
```

**关键约束**（写进每个模板）：
- **只读不写**：评审代理不改文件，改动全部由我执行——否则合并权就散了
- **给证据**：每个结论附 `file:line`
- **说不知道**：不确定就写「不确定」，不猜

| 模板文件 | 用途 | 委派对象 |
|---|---|---|
| `security-review.md` | 一个 PR / 一个包的安全评审 | claude |
| `impl-review.md` | 代码结构与抽象评审 | codebuddy |
| `qa-review.md` | 测试有效性评审 | qoder |
| `doc-check.md` | 文档一致性机械核对 | codearts |
| `req-critique.md` | 需求可判定性批判 | opencode |
| `perf-review.md` | 性能路径分析 | claude |

## 3. 委派协议（我怎么交接）

### 3.1 一次委派的形状

```bash
# 我组装提示词：模板 + 具体目标 + 当轮上下文
cat .team/prompts/security-review.md \
  | sed "s|@@TARGET@@|internal/discovery/|" \
  | sed "s|@@ROUND@@|Round 4: PR-M2 second cut|" \
  > /tmp/delegate.md

# 委派（超时必须显式：headless 代理没有内建时限）
timeout 300 claude -p "$(cat /tmp/delegate.md)" 2>&1 | tee /tmp/review-security.log
```

### 3.2 验收他们的产出

评审回来的东西我按同样标准核：**结论要附 `file:line`，我抽查后才进 Round 报告**。
上一轮（mesh 评审）我已经核对出 2 项失实指控——**外部代理的结论同样要被核实**。

### 3.3 失败处理

| 情况 | 处理 |
|---|---|
| 超时 / 网络错（codex 现状） | 换备份岗，不重试超过一次 |
| 结论无证据（没 file:line） | 打回重问，不猜它的意思 |
| 与代码事实矛盾 | 以代码为准，记进 Round 报告 |

## 4. 与 TEAM.md / ROUND-LOG 的关系

```
TEAM.md        六个虚拟角色的门（不变，仍是合并判据）
     ↑ 真实代理补强
WORKTEAM.md    角色 → 代理的映射 + 提示词 + 委派协议（本文）
     ↓ 每轮产出
ROUND-LOG.md   Round 报告新增「外部评审」列：哪家代理、什么结论、采纳/驳回
```

**虚拟门不撤销**：外部代理缺席时（全断网），我仍然一个人过六道门——
制度的价值在门本身，不在于门外站着谁。

---

## 5. 边界（不做什么）

- **外部代理不直接提交代码**。所有 commit/push/merge 由我执行（T-1.10 口头放行链不变）。
- **不并行委派写码任务给多家**再挑一个——那是浪费，且合并权模糊。写码归我，评审归他们。
- **不用他们跑 CI**。CI 是客观的，不需要模型的意见。
